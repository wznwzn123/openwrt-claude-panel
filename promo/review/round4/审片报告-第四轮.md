## 1. 总体评价

**一句话结论：这是一支技术交付干净、界面渲染精致、配色统一的「产品功能幻灯片」，还不是一支有电影感的商业宣传片。片中有一处把仓库里不存在的功能当成已实现功能来展示（S 级），另有 AI 配音辨识度高、品牌名发音存疑、结尾音乐没有收住、高潮段几乎静止等明显问题。按现状不建议正式发布；修完 S 级和 A 级问题之后可以发布，不需要整片重做。**

优点是真实的：大部分宣传点在仓库和官网都能找到依据，演示数据有角标声明，手机界面由真实面板代码渲染，清晰度高，数据细节大多自洽（例如客厅电视 31.2 GB + 410 MB = 31.6 GB，前后对得上）。技术参数达到母版级：无黑屏故障、无卡帧、无削波、响度 -14 LUFS。

主要短板：
1. **真实性**：安卓客户端「局域网自动发现」在仓库代码、README、官网中都找不到依据，而且与产品「服务只监听 127.0.0.1」的架构相矛盾（S 级）；「仅占 2MB 闪存」的标题去掉了「本体」这个限定；「端到端加密备份」「毫秒级切换高速专线」措辞超过了真实能力。
2. **影像语言**：逐帧运动能量测量显示，约一半时长画面几乎静止（每秒帧差均值 < 0.4/255）。主要的镜头手段是 2.5D 手机模型平移 / 倾斜，加上卡片逐条出现，PPT 感明显。手机模型出现了十几次。第四幕本应是高潮，却是全片最静的一段：两块玻璃面板静置 16 秒，只有文字在变。
3. **声音**：旁白是 Edge 在线 TTS「云扬」，国内观众对这个音色很熟悉，带有营销号的联想；人声频带上限约 11–12 kHz，听感偏闷。「Claude」在不加提示词的 ASR 中两次都被转写为「Cloud」，「破界」被转写为「破解」，「毫秒」三次被转写为「好秒」，都需要人耳复核。最后一句旁白在 89.3 秒说完，全混音在约 0.5 秒内掉到 -40 dB，没有尾音和留白。

### 1.2 审片方法（可复现）

- 全片每 0.5 s 抽帧（180 帧）做成带时间码的联系表逐张看过；在切点和关键镜头另截 1920×1080 原帧共 40 余张，对终端文字、手机 UI、通知卡片、安卓界面做 2–3 倍放大。
- 自动检测：`blackdetect`、`freezedetect`、逐帧 scene score、160×90 灰度逐帧差分（判断重复帧和运动能量）、`ebur128`、`astats`、`silencedetect`、全片和片尾频谱图。
- 旁白：用 faster-whisper small 全片转写，再分段重转写（无提示词 / 有提示词 / 英文解码三种方式），与字幕逐句核对。
- 真实性：对照仓库 `README.md`、`src/`（`cgi-bin/mcp`、`cmcp-watchdog`、`cmcp-backup`、`cmcp-autosw`、`init.d/claude-mcp`、`panel/index.html`）、`android/`、`docs/compatibility.md`，以及官网首页文本、安装包下载链接（HTTP 200）、GitHub Releases 列表。
- **感知局限**：我无法像人一样连续观看和试听。音色自然度、音乐情绪、混音听感等主观项，依据是频谱、电平统计和 ASR 识别结果，相关结论标注「待用户试听确认」。

## 4. 问题清单

> 优先级：P0 = 发布前必须修改；P1 = 强烈建议本轮修改；P2 = 建议修改；P3 = 可选。

### S 级（严重：影响产品可信度 / 不修改不应发布）

**S-1　安卓客户端「局域网自动发现」在仓库中无依据，并与产品架构矛盾**
- 时间戳：44.5–46.0 s（安卓屏显示「局域网自动发现中… 同一 Wi-Fi 下自动搜索面板」→「✓ 已发现：家里 · AX3000T」）；44.5–53.5 s 副标题持续显示「v3.0.2 · **局域网发现** · 多路由切换」
- 具体表现：画面以雷达扫描动画演示安卓 App 在同一 Wi-Fi 下自动发现路由器并直连。
- 为什么是问题：
  - `android/app/src/main` 中搜索 NsdManager / discover / InetAddress / 局域网 / mdns / ssdp，均无匹配。
  - README 与官网写明的「添加路由器」方式只有 **扫码 / 相册识别 / 粘贴 / 手动添加** 四种。
  - README 安全说明写明「服务只监听 `127.0.0.1:18765`，局域网和公网都无法直接访问，只能经过 Cloudflare 隧道」（`src/init.d/claude-mcp` 第 8 行 `uhttpd -p 127.0.0.1:18765` 可印证）。按这个架构，局域网发现无法按画面描述的方式成立。
  - 这个卡片是为替换原画面中的二维码而做的，但替换品是一个产品并不具备的功能。任务书明确把「将尚未实现的功能包装成已实现功能」列为重点核查项。
  - 按独立性要求，本报告不断言「绝不存在」（作者可能有未公开的分支），措辞为「仓库、README、官网三处均无依据，且与公开架构矛盾」。除非作者能提供实现证据，否则应按虚构功能处理。
- 对整体影响：熟悉产品的用户装上 App 找不到这个功能，会连带怀疑其他所有宣传点；对一个以「安全隔离」为卖点的产品，宣传「局域网自动发现」还会让懂行的观众误以为服务暴露在局域网上。
- 修改建议：改成真实流程。推荐「扫码添加」：取景框对准面板「添加新手机」页，二维码区域用模糊块或取景框遮挡，不必出现真实二维码，可兼顾合规要求。或者改成「粘贴登录地址 → 添加成功」。副标题改为「扫码添加 · 多路由一键切换」，同时去掉 `44-lan-radar`、`46-lan-found` 一类音效。
- 优先级：**P0**

### A 级（明显缺陷：严重影响观感或可信度）

**A-1　「仅占 2MB 闪存」标题去掉了「本体」限定，与 README 的空间要求不符**
- 时间戳：16.5–28.0 s 标题副行「原生 ucode 驱动 · 仅占 2MB 闪存」；21.5–28.0 s 卡片「仅占 2MB 闪存空间 · 兼容 OpenWrt 22.03+ · Kwrt · ImmortalWrt」；21.6–23.4 s 字幕「本体仅占 2MB 空间」
- 具体表现：旁白和字幕说的是「本体」，正确；但画面上两处大字标题写成「仅占 2MB 闪存」，并紧挨着「兼容……」。
- 为什么是问题：README 原文是「约 2 MB 闪存空间；`cloudflared` 本身约 30 MB，空间不够请先扩容 overlay」。而本片的核心卖点之一正是「依托 Cloudflare 加密隧道」，实际部署通常需要约 32 MB。
- 对整体影响：16 MB 闪存的小机型用户会据此判断「能装」，装不上就会觉得被误导，属于夸大兼容性。
- 修改建议：标题改为「面板本体约 2MB」，卡片小字补「隧道组件另需约 30MB」；或把卡片主题换成「零 Python / Node / Docker」，避开容量数字。
- 优先级：**P1**

**A-2　品牌词「Claude」发音存疑（待用户试听确认）**
- 时间戳：12.9–14.5 s（「OpenWrt Claude Panel」）；52.9–54.8 s（「接入 Claude 自定义连接器」）
- 具体表现：Whisper 在不给提示词时两处都转写为「Cloud」（中文解码「接入Cloud自訂已連接期」，英文解码「Join Cloud…」；产品名段「OpenWRT Cloud Panel」）。加入提示词后才得到「Claude」。同一段中 ASR 对「OpenWrt」的置信度也很低（0.03–0.29）。
- 为什么是问题：「Claude」是产品名的核心词。如果实际读音接近 /klaʊd/（cloud），观众会听成「云面板」，正好与片中大量出现的「云端 / Cloudflare」混在一起，品牌辨识被削弱。
- 对整体影响：品牌名在全片只念两次，两次都可能念错。
- 修改建议：先请用户试听 13.0–14.5 s 和 53.0–53.8 s。如果确认读错，改用 SSML 音素或改写拼读（例如给 TTS 输入「克劳德」，屏幕仍写 Claude），或者整段换真人配音。
- 优先级：**P0（若试听确认）**

**A-3　旁白为高辨识度的 Edge 在线 TTS「云扬」，AI 配音痕迹明显，且有多处易误听的字（待试听确认）**
- 时间戳：全片；重点在 14.9 s「破界登场」（三种解码均转写为「破解 / 破戒」）、35.1 s 和 60.4 s「毫秒」（三次均为「好秒」）、16.5 s「路由器原生」（转写为「路由既原生 / 寄源声」）、85.0–87.5 s 网址（无提示词时为「YRLAW520 / yrlaw220」）
- 具体表现：配音稿 `voice/script.json` 使用 `zh-CN-YunyangNeural`，实测中位基频约 132 Hz，与之吻合。全片频谱显示，人声能量在约 11–12 kHz 以上几乎为零（Edge TTS 24 kHz 采样的典型特征），只有音效段有高频。
- 为什么是问题：
  1. 「云扬」是国内短视频平台上最常见的 AI 播报音色之一，观众很容易产生「营销号」联想，与片中「电影级」的视觉定位冲突。
  2. 「破界 pò jiè」与「破解 pò jiě」只差一个声调，对路由器 / 安全类产品，「破解」的联想是负面的。
  3. 频带受限，在耳机和大屏上听感偏闷。
  4. 工程 `promo/README.md` 自己写明「商用发布前请自行确认该语音的使用条款」，即授权**待核实**。
- 对整体影响：声音是观众判断「专业 / 业余」最快的线索，目前是全片质感的最大拖累之一。
- 修改建议：首选真人配音（男中低音，语速可比现在慢约 5%）；次选有明确商用授权的高品质 TTS，并逐字校对「破界、毫秒、Claude、ucode、yrlove」。如果暂时保留 TTS，至少把「破界登场」改写为「正式登场 / 全新登场」，避开同音风险。
- 优先级：**P0（授权核实）/ P1（音色替换）**

**A-4　结尾没有收束：最后一句说完约 0.5 秒内整体衰减到底**
- 时间戳：87.6–90.0 s
- 具体表现：最后一句「即刻唤醒你的智能路由」在约 89.30 s 结束。全混音 RMS 从 89.01 s 的 -11.9 dB 降到 89.31 s 的 -29.6 dB、89.46 s 的 -41.4 dB，90.0 s 归零。频谱显示低频配乐与人声在 89.3 s 同时截止，之后只有约 0.5 s 的衰减尾巴。
- 为什么是问题：落版是品牌记忆点，但画面上的 logo 没有获得独立的「声音落点」（终止和弦 / 品牌音 / 余响）。观众的感受会是「话说完片子就断了」。
- 对整体影响：直接削弱结尾的记忆点，在 B 站这类会看到片尾的平台上尤其明显。
- 修改建议：让最后一句在约 87.5 s 前说完（删掉一个修饰词，或把网址只放在画面上、不读出来），后面留 1.5–2.5 s 给终止和弦和 logo 定格；或者把总长放宽到 92–93 s。音乐需要一个真正的结尾段落，不要只做淡出。
- 优先级：**P1**

**A-5　高潮段与多处长停留几乎静止，PPT 感强**
- 时间戳：13–19.5 s（英雄镜头静止，仅换主题皮肤）；20.5–27.5 s（四张卡片逐条出现，约 7 s）；45–53.5 s（双手机并排静置，50.5–52.9 s 无旁白）；61–73.5 s（第四幕两块面板静置约 12 s，只有文字变化）；75–81 s（看门狗面板静置）
- 具体表现：逐秒帧差均值低于 0.4（满分 255）的秒数约占全片一半；这些段落只有背景极光缓慢漂移和局部文字动画。第四幕是叙事高潮，运动能量却与第二幕的静止段相当。
- 为什么是问题：商业片的高潮需要镜头调度（推近、切特写、反打、节奏加速），这里只是「同一构图里换字」。观众在这段最容易划走。
- 对整体影响：整片读起来像带动效的发布会幻灯片，这是「电影感」得分偏低的主因。
- 修改建议：见第 8 节「第四幕重构」。核心做法：把同一构图拆成 3–5 个镜头（输入框特写 → 发送 → 工具调用标签微距 → 右侧状态行推近切换 → 回执），镜头时长 1.0–2.0 s，切点卡在鼓点上；45–53.5 s 压缩到 5 s 以内；卡片逐条出现改成快切。
- 优先级：**P1**

### B 级（可改善问题：影响局部质量或局部可信度）

**B-1　分层拆解图里的伪终端信息失真，且与产品安全设计矛盾**
- 时间戳：20.5–28.0 s（左后层，放大见 `work/crop_term.png`）
- 表现：显示 `uhttpd -p 0.0.0.0:8…`、`ucode /www/cgi-bin/`、`cmcp-watchdog --30s`、`du -sh /www/panel → 2.0M`。
- 为什么是问题：真实配置是 `uhttpd -p 127.0.0.1:18765 -h /www-claude-mcp`，面板目录是 `/www-claude-mcp/panel/`（仓库中实测 832 K），看门狗是没有 `--30s` 参数的 shell 脚本。`0.0.0.0` 意味着监听所有网卡，正好与「只能经隧道访问」的安全卖点相反。技术观众暂停截图就能挑出来。
- 影响：降低技术可信度。
- 建议：改成真实输出：`uhttpd -f -p 127.0.0.1:18765 -h /www-claude-mcp`，`/www-claude-mcp/panel`，`/usr/sbin/cmcp-watchdog`。
- 优先级：P1

**B-2　「端到端加密云端备份」措辞超过真实能力，且没有说明版本限制**
- 时间戳：76.6–77.7 s 字幕「加密云端备份」；77.0–81.8 s 推送卡「每日**端到端加密**云端备份已就绪」；82.0–85.0 s 自建版卡「**端到端加密**备份」
- 为什么是问题：`src/bin/cmcp-backup` 注释和官网「安全」一节写明：有 openssl 时才自动加密，没有时需要在面板里点「开启加密」安装，「没开启加密的备份仍然原样存在云端」。云端备份、微信推送、断电断网判断只有自建完整版和托管版才有，精简版没有。「端到端」是很强的安全承诺。
- 影响：夸大安全性，属于任务书点名的核查项。
- 建议：改为「可选加密云端备份」或「本地加密后上传」，删掉「端到端」；在第五幕某处加小字「完整版 / 托管版」。
- 优先级：P1

**B-3　「毫秒级切换高速专线」混淆了延迟与切换耗时，并超出合规改写范围**
- 时间戳：60.4–62.3 s（旁白 + 字幕）；35.1–36.4 s「毫秒级批量测速」
- 为什么是问题：画面上的 28 ms 是线路延迟，不是切换耗时。经由 Claude 对话切换的端到端耗时以秒计。「高速专线」暗示运营商级专线，已经超出对照表「节点 → 线路」的范围。
- 建议：改为「一句中文，秒切低延迟线路」；测速句改为「一键批量测延迟」。
- 优先级：P2

**B-4　「六大套件全自动识别 · 线路异常自动切换」把两个适用范围不同的能力并列**
- 时间戳：28.0–38.0 s 顶部标题；31.8–34.7 s 字幕；32.5 s 前后底部弹层只列出 3 个套件
- 为什么是问题：六种插件自动识别属实（OpenClash、Nikki、PassWall、PassWall2、HomeProxy、SSR Plus+）；但节点挂了自动切换只有 OpenClash 支持（官网原文为「OpenClash 还能……节点挂了自动换」，`cmcp-autosw` 只读 openclash 配置）。另外旁白说「六大」，画面只看得到 3 个。
- 建议：标题拆为两行，或写成「六大套件自动识别 · 智能调度套件异常自动切换」；弹层向上滚动露出更多条目，或给出「6」的计数。
- 优先级：P2

**B-5　演示数据前后矛盾**
- 时间戳：12–28 s 首页「今日流量 ↓44.1 GB ↑3.4 GB」与 40–44 s「今日合计 47.5 GB」一致，但 29–38 s 右侧「流量统计」显示「今天一共 31.4 GB」，而且客厅电视一台就有 31.6 GB；79.5–81.8 s 推送卡「路由器 23:41 离线 · 刚刚」，而全片时钟统一为 21:46。
- 影响：细心观众会注意到；在已声明「演示数据」的前提下仍会削弱可信度。
- 建议：统一当日总量；推送时间改为昨日（如「昨晚 23:41」）或改到 21:4x。
- 优先级：P2

**B-6　「原生安卓客户端」装在带灵动岛的 iPhone 机身里**
- 时间戳：44.5–53.5 s 右侧手机
- 影响：设备形态错误，在 B 站数码类观众中很容易被吐槽。
- 建议：换成 Android 机身（挖孔屏、无灵动岛），状态栏也改为 Android 样式。
- 优先级：P2

**B-7　版本号过时且彼此不一致**
- 时间戳：12.5–28 s「v3.1.1」；44.5–53.5 s 安卓「v3.0.2」
- 依据：GitHub Releases 最新版为 v3.1.2（2026-11-12 发布），App 版本与 Release 同号（官网 `/api/app/version` 返回 3.1.2）。
- 建议：去掉版本号（避免很快过时），或发布时统一为当时的最新版。
- 优先级：P2

**B-8　文字层叠，信息重复**
- 时间戳：9.0–10.3 s 同屏 5 层文字（顶部标语、OPENWRT、中文主张、英文小字、字幕）；58–74 s 下三分之一胶囊「内置 30+ 项路由底层工具 · 中文对话言出法随」常驻 16 s，与字幕上下叠成两条；21–28 s 卡片与字幕说同一句话
- 建议：同一句话只出现一次（大字或字幕选一个）；下三分之一胶囊出现约 2.5 s 后收起。
- 优先级：P2

**B-9　字幕框压住手机 UI**
- 时间戳：32.5–34.7 s、35.1–38.1 s（字幕盖住中间手机的底部导航「重启 / 更新线路源」）；41.2–43.9 s
- 建议：这几段把手机构图上移约 60–80 px，或给字幕加安全区。
- 优先级：P2

**B-10　旁白与画面错位**
- 时间戳：16.0–19.6 s 旁白讲「扎根原生 ucode 与 uhttpd」，画面在切换「外观 · 深色模式」「相册背景磨砂玻璃」，旁白全片没有提到主题功能；52.9–54.0 s 旁白「接入 Claude 自定义连接器」，画面仍是安卓双机。
- 建议：主题切换挪到「掌中面板」一句之下，或删掉；第四幕画面提前约 1.1 s 入场，与旁白对齐。
- 优先级：P2

**B-11　开场巨型「OPENWRT」与「旧时代的路由繁琐，至此终结」并置，有歧义**
- 时间戳：6.5–10.5 s
- 为什么是问题：产品本身运行在 OpenWrt 上。把 OpenWrt 的名字做成全片最大的字，再配上「旧时代……终结」，一种读法是「OpenWrt 过时了」，另一种是「这是 OpenWrt 官方作品」。两种都不是想要的效果，还涉及第三方商标。
- 建议：主张改为「旧式后台的繁琐，至此终结」，并在镂空字后加「换一种方式打开 OpenWrt」；或者把镂空字换成产品名。
- 优先级：P2

**B-12　开头 3 秒钩子偏弱**
- 时间戳：0.0–3.0 s
- 表现：低对比度的灰色 LuCI 英文页面，加上相机取景框 HUD（ISO / REC）。第一处有冲击的中文信息「公网 IP 缺失，无法远程连接」要到约 2.0 s 才出现，而且在画面下半部。
- 建议：0 s 直接给红色错误提示的特写，配一个硬音效；或者冷开场 1.5 s 先展示「一句中文 → 路由器执行」的结果，再回到痛点。

**B-13　第三方商标与平台合规适配不彻底（待用户评估）**
- 时间戳：58–74 s 自绘「Claude · 自定义连接器」窗口，使用橙色方块图标；85–90 s 落版「GitHub wznwzn123/…」「GitHub 点亮 Star」；22–28 s、74–82 s 画面中的「Cloudflare」字样
- 为什么是问题：

  2. 背景说明称「全片不出现境外平台名」，但 GitHub 和 Cloudflare 仍在画面上（旁白保留 Cloudflare 是用户的既定选择，此处只指出画面与规则不一致）；
  3. 在国内平台推广一个以 Claude 为核心的产品，其平台合规性**待用户自行评估**，本报告不下结论。
- 建议：落版加一行小字「第三方开源项目，与 Anthropic、OpenWrt 官方无关」；自绘界面角标改为「示意画面」。是否保留 GitHub 字样请用户按平台策略决定。

**B-14　配乐与混音：峰值长期贴着限幅线，配乐情绪待试听**
- 时间戳：全片，尤其 53–90 s
- 表现：几乎每个 0.5 s 窗口的样本峰值都在 -2.3 到 -2.7 dBFS，说明限幅器一直在工作，可能带来「被压扁」和泵吸感；第四、五幕低频（20–80 Hz）明显加厚。配乐是 `audio/synth.py` 程序合成，没有采样。49.5–53 s 的纯配乐段电平约 -30 dB，听起来可能空洞。
- 建议：先试听；如果听感发扁，把母带目标降到约 -15 LUFS，减少限幅量；第四幕的低频垫底在人声频段（150 Hz–4 kHz）做侧链让位。配乐建议换成有授权的成品曲，或请人做专门编曲，需要有明确的「起 / 承 / 高潮 / 收」四段结构。
- 优先级：P2（待试听）

**B-15　15 秒循环预览不无缝**
- 时间戳：`preview-loop-15s.mp4` 14.97 s → 0.00 s
- 表现：末帧是 Claude 双屏，首帧是英雄手机，首尾帧灰度平均差 40/255，是硬跳（见 `work/loop_seam.png`）；10 s 处有多层半透明叠化，画面发脏。工程 README 称其为「无缝循环」。
- 建议：结尾回到英雄构图，或首尾做 0.5 s 叠化匹配。
- 优先级：P3

**B-16　竖屏 60 s 版 UI 过小**
- 时间戳：`promo-vertical-60s.mp4` 约 26–31 s（承载「暂停儿童平板」的手机只占画面高度约 1/4）及多处

## 5. 分幕评价

**第一幕　痛点（0.0–12.0 s）**　评价：中上
- 有效：「手机缩放旧后台 → 端口映射失败 → CGNAT 无公网 IP」三步，痛点链条准确，正是目标用户的真实痛点；CAM 01/02/03 三联屏有监控室的压迫感；6.5–10.5 s 的镂空字和 10.5–11.5 s 穿过字母 O 的推镜是全片最好的转场。
- 问题：开头 3 秒对比度低、钩子不够硬（B-12）；HUD 伪遥测和取景框是模板化元素（C-1）；「OPENWRT + 至此终结」有歧义（B-11）；9–10 s 文字层太多（B-8）。

**第二幕　产品登场（12.0–28.0 s）**　评价：中
- 有效：英雄镜头（12–15.5 s）是全片最佳单帧；分层拆解图概念好。
- 问题：16 秒里有约 11 秒近乎静止；主题换肤与旁白错位（B-10）；卡片逐条出现是典型 PPT 动效（A-5）；「仅占 2MB 闪存」去掉了限定（A-1）；伪终端失真（B-1）。

**第三幕　功能巡礼（28.0–54.0 s）**　评价：中下
- 有效：信息量大，画面与旁白大多一一对应（测速 ↔ 线路列表，定时断网 ↔ 暂停弹层，面板锁 ↔ 密码键盘），38.5–44 s 柱状图到暂停弹层这一组节奏最好。
- 问题：三机并排、双机并排的手机模型反复出现；S-1 虚构功能出在这一幕；安卓装在 iPhone 机身里（B-6）；49.5–53.5 s 拖沓；数据矛盾（B-5）；字幕压住 UI（B-9）。这一幕 26 秒，压到 20 秒左右观感会好很多。

**第四幕　AI 高潮（54.0–74.0 s）**　评价：中下（以「高潮」的标准衡量）
- 有效：对话 → 光束 → 状态切换的因果设计清楚；三条指令（切线路 / 查占用 / 定时休眠 + 自动备份回滚）覆盖了 AI 版的核心价值；UCI 片段和「一键回滚」体现了安全感。
- 问题：全片最需要冲击力的一段，视觉上却最静（A-5）；关键词云老套（C-2）；下三分之一胶囊常驻（B-8）；「毫秒级切换高速专线」夸大（B-3）；与第三幕情节重复（C-4）；「Claude」读音存疑（A-2）。

**第五幕　守护与落版（74.0–90.0 s）**　评价：中
- 有效：看门狗面板与外部标注的对应关系清楚；托管版 / 自建版两张卡加安装命令，信息务实，命令与 README 一字不差，下载链接可用；落版干净。
- 问题：「端到端加密」夸大（B-2）；推送时间与时钟矛盾（B-5）；HUD 风格回归，与中段的极光玻璃风格割裂（作为首尾呼应可以接受，但伪数据应删）；结尾硬收（A-4）。

## 6. 声音评价

**旁白**
- 音色：Edge TTS「云扬」男声（配音稿声明，实测中位基频约 132 Hz），播音腔、平稳，但 AI 合成痕迹和营销号联想明显（A-3）。
- 清晰度：Whisper small 能正确识别绝大部分句子，整体可懂度合格。但「Claude → Cloud」「破界 → 破解」「毫秒 → 好秒」「yrlove → YRLAW」反复出现，提示这些字的发音或声调可能有问题。**待用户试听确认**（建议重点听 13.0–15.4 s、35.1–36.4 s、53.0–54.8 s、60.4–62.3 s、85.0–87.5 s）。
- 频响：人声高频在约 11–12 kHz 处截止，缺少「空气感」。
- 文案：四字格密集（破界登场、囊括运维万象、言出法随、精准判明），气势有了，但信息被修辞稀释；整片没有一句可以单独传播的「核心主张句」。

**音乐**
- 程序合成（`audio/synth.py`，无采样）。从频谱看，第一到三幕配乐较稀，第四幕起低频垫底明显加厚，有「前低后高」的递进设计。
- 49.5–53 s 纯配乐段约 -30 dB，可能显得空。
- 结尾没有终止段落，与人声同时在 89.3 s 截止（A-4）。
- 情绪是否到位、是否有廉价合成器感：**待用户试听确认**。

**音效**
- 剪映草稿含约 140 个音效文件，工程内 78 条音效 cue，覆盖点击、打字、雷达、提示音、冲击等，与画面动作同步良好（频谱上 11–13 s 的穿越 riser、5.8 s 的切黑冲击、各处 whoosh 都清楚可见）。
- 风险：密度偏高，几乎每个 UI 动作都有声音，容易显得「忙」；`lan-radar` 和 `lan-found` 要随 S-1 一起删除。

**混音与母带**
- 合格项：-14.0 LUFS、-1.7 dBTP、无削波、无掉音、左右声道相关性 0.99（接近单声道，在手机外放上安全）。
- 风险项：峰值长期贴着约 -2.5 dBFS，限幅偏重（B-14，待试听）；第四、五幕配乐整体抬高，人声 / 配乐比需要人耳确认是否仍然舒适（ASR 可懂度未见下降，初步判断没有严重掩蔽）。

## 8. 修改建议

### 8.1 必须修改（发布前）

1. **重做安卓卡片（S-1）**：44.5–46.5 s 换成「扫码添加」或「粘贴登录地址」的真实流程；副标题改为「扫码添加 · 多路由一键切换」；机身换成 Android 样式（顺带解决 B-6）；去掉雷达类音效。工作量小（单个组件 + 一段音效），只需重渲第三幕。
2. **修正事实措辞（A-1、B-1、B-2、B-3）**：「仅占 2MB 闪存」改为「面板本体约 2MB」；伪终端改成真实的 127.0.0.1:18765 和真实路径；「端到端加密」改为「可选加密」；「毫秒级切换高速专线」改为「秒切低延迟线路」。只改文字，涉及第二、四、五幕。
3. **配音（A-2、A-3）**：先由用户试听确认「Claude / 破界 / 毫秒」的发音；如有误，最低限度要修正这几个词（SSML 或改写）。同时核实 TTS 商用授权；拿不到授权就必须换声。

### 8.2 强烈建议（本轮）

4. **结尾声音收束（A-4）**：最后一句在约 87.5 s 前结束，加 1.5–2.5 s 终止和弦或品牌音并定格 logo；必要时把总长放宽到 92 s。
5. **第四幕重构（A-5）**，建议分镜：
   - 54.0–55.5 s　黑场中「Claude 自定义连接器」字样亮起，替代关键词云；
   - 55.5–57.0 s　手指在输入框打字的特写（微距、浅景深）；
   - 57.0–58.0 s　发送；「调用工具 · 线路切换」标签弹出特写；
   - 58.0–59.5 s　光束穿越，切到右侧状态行推近，「超时 → 当前」翻转，配鼓点；
   - 59.5–61.0 s　拉开到双屏全景，回执出现；
   - 后两条指令照同样方式「特写 + 结果」快切，每条不超过 4 s，省下的时间留给结尾。
6. **压缩静止段**：第二幕卡片逐条出现（20.5–27.5 s）改为 3 个快切镜头；第三幕 49.5–53.5 s 压到约 1.5 s，并让第四幕画面提前约 1.1 s 入场。
7. **配乐**：换成有明确起承转合的授权配乐或专门编曲，第四幕给真正的高潮段，第五幕给收束段；母带适当减少限幅（B-14）。

## 9. 最终发布建议

- **是否建议正式发布？**
  **按现状不建议。** S-1（虚构「局域网自动发现」）会直接损害产品可信度；A-2 和 A-3 配音问题需要先试听确认并核实授权。这三项处理完、A-1 措辞改完之后，可以作为 B 站 / 官网首发版本发布。如果想达到「商业宣传片」水准，还需要完成第 8.2 节。

- **是否建议重新制作部分镜头？**
  建议**局部重做，不整片重做**：第三幕安卓卡片（44.5–53.5 s）必须重做；第四幕（54–74 s）建议重新分镜；片尾音频（87–90 s）重做收束。其余镜头以改字、调时长为主。

- **哪些镜头应该保留？**
  12.0–15.5 s 英雄镜头；6.5–11.5 s 镂空字与穿越字母 O 的转场（改主张文案即可）；20.0–23.5 s 分层拆解图（修终端内容）；38.5–44.0 s 流量柱状图到暂停弹层；58.0–61.5 s 光束联动切换；74.0–81.5 s 看门狗标注；85.0–90.0 s 落版画面。

- **哪些镜头最值得优先修改？**
  ① 44.5–53.5 s 安卓卡片（S-1，可信度）；② 54–74 s 第四幕高潮（A-5，观感）；③ 87–90 s 结尾声音（A-4，记忆点）；④ 16.5–28 s「仅占 2MB 闪存」及伪终端（A-1、B-1，可信度）。

- **如果只能修改三个地方，应该修改什么？**
  1. **删掉「局域网自动发现」**，换成真实的扫码 / 粘贴添加流程，机身改为 Android（44.5–53.5 s）。这是唯一的 S 级问题，修改成本最低，可信度收益最大。
  2. **解决配音**：先试听确认「Claude / 破界 / 毫秒」的读音并核实 TTS 授权；条件允许就整片换真人配音，至少修正品牌词发音。声音是观众判断专业度最快的依据。
  3. **重做第四幕节奏并补上结尾收束**：把 54–74 s 拆成「特写 + 结果」的快切，空出约 2 s 给 89–90 s 的终止和弦和 logo 定格。高潮和结尾决定观众记住什么，这一处改动对观感提升最大。
