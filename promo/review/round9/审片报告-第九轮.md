## 1. 总体评价

这是一支**做工干净、信息诚实、但电影感和声音都偏「模板化」的动态图形产品片**。

做得好的地方：
- 产品界面全部来自仓库代码实机渲染，演示数据、示意画面和加速呈现都打了角标。
- 32 个连接器工具名与源码逐一对得上。
- 合规改写口径执行一致。
- 字幕与旁白基本同步（误差约 0.1 s）。
- 技术交付指标合格：−14.1 LUFS，真峰值 −1.5 dBTP，无黑帧、无卡帧、无解码错误。

主要短板有四处：
1. **画面始终是「深色极光底 + 玻璃卡片 + 手机模型」**，没有一个真实拍摄镜头，手机模型在第二、三、五幕反复出现，第二幕版式接近 PPT。
2. **声音是全片最弱的一环**：TTS 旁白；「Claude」两次被转写为「Cloud」；程序合成配乐基本是循环，情绪起伏小。
3. **片中写死的版本号 v3.1.3 已经过时**：GitHub 上今天已发布 v4.0.0（强制更新）和 v4.0.1，新版面板顶栏多了通知铃铛。
4. 有两段约 3 s 的无旁白静态停留，节奏塌陷。

结论：**合格，但仍有明显提升空间（70/100）**。全片没有 S 级问题，A 级问题 4 条。其中 A1（版本号）是可测量的事实时效问题，修改成本很低；A2（Claude 读音）需要用户试听确认。

## 4. 问题清单

> 每条依次说明：时间戳｜表现｜为什么是问题｜对成片的影响｜修改建议｜优先级。依据类型标【测】或【听/看·待确认】。

### S 级（严重）
**无。**全片没有发现虚构功能、把未实现功能说成已实现、严重音频故障或无法播放的问题。

### A 级（明显缺陷）

**A1　版本号过时｜13.0–28.5 s（标题胶囊「开源项目 · MIT · v3.1.3」）、46.9 s（「安卓 App v3.1.3」）、15 s 循环全程、竖屏 10–14 s｜【测】**
- 表现：片中三处写死 v3.1.3。GitHub Releases API 显示，v4.0.0 于 2026-11-14 02:38Z 发布，说明里写着「这次所有人都要更新到 4.0」；v4.0.1 于 08:25Z 发布。v4.0 的面板顶栏新增了通知铃铛和「消息与帮助」入口；v4.0.1 的 `index.html` 含「消息与帮助」，本地分支不含。
- 为什么是问题：片子展示的是官方已要求强制升级的旧版本。观众今天安装会拿到 v4.0.1，顶栏与片中不同。片子写的是一个已经被替代的版本号。
- 影响：削弱「实机」的可信度。技术观众，尤其是 B 站用户，很容易发现。
- 建议：最低成本做法是去掉画面里的具体版本号（例如改成「开源项目 · MIT」）；如果要保留版本号，就按 v4.0.x 重新采集面板截图，至少把顶栏换成带铃铛的版本，并统一改为 v4.0.x。
- 优先级：**发布前必改**（成本低）。

**A2　「Claude」读音被识别成「Cloud」｜12.76 s（「OpenWrt Claude Panel」）、55.50 s（「AI 版接上 Claude」）；竖屏 8.8 s、26.1 s 同样如此｜【测】+【听·待用户试听确认】**
- 表现：faster-whisper small 在主片和竖屏中，把两处「Claude」都转写成「Cloud」（置信度 0.81 / 0.86）。「Panel」识别正确。
- 为什么是问题：同一段旁白里还有「Cloudflare」。观众可能把产品名听成「OpenWrt Cloud Panel」，品牌记忆就错了。
- 影响：品牌名是传播的核心资产。若试听确认读音偏向「Cloud」，等同于品牌名念错。
- 建议：保持「按英文读」的前提下，可尝试三种做法：(1) 用 SSML `<phoneme>` 或音标强制读 /klɔːd/；(2) 合成文本写成「Claude（克劳德）」，只取英文部分的发音；(3) 换另一个对英文专名发音更准的免费中文 TTS 声线。修改后用同一 ASR 复测，以转写出「Claude」作为验收标准。
- 优先级：**试听确认后决定**；确认读偏即必改。

**A3　手机模型反复出现，第二幕版式接近 PPT｜12–28.5 s、28.5–53.6 s、74–81.8 s；15 s 循环中占约 70%｜【看·待确认】**
- 表现：全片约 55 s 的画面主体是悬浮的手机模型（单台、三台或两台）。第二幕是「左大标题 + 三张要点卡 + 右手机」的静态构图，持续约 9 s（20–28.5 s）。第三幕三台手机并排，每台只占画面高度约 1/3（例如 30 s）。
- 为什么是问题：任务书 A 维度明确把「重复的手机模型展示」「明显 PPT 感」列为检查项。反复使用同一视觉母题，会让后半段失去新鲜感。
- 影响：观感更像「功能说明幻灯片」，不像商业广告。这是视觉分只有 16.5 的主要原因。
- 建议：保留 13–20 s 的主视觉手机；第二幕改成全屏界面推近或分层拆解动画，取消要点卡停留；第三幕至少一段改为单个界面全屏、关键控件放大的「真实操作」镜头（例如点「测速」按钮后延迟数字跳出）；第五幕的手机可以用全屏「断线记录」界面加推送卡片替代。
- 优先级：可选优化中的高优先级（属于重新制作部分镜头）。

**A4　配乐循环感强、情绪起伏小｜12–88 s｜【测】+【听·待试听确认】**
- 表现：
  - 【测】BGM 分轨按 4 小节（116 BPM，8.28 s）分块，相邻块频谱余弦相似度 0.937–0.981，第四、五幕达到 0.97–0.98。
  - 【测】全片 LRA 3.8 LU；54 s「Claude 登场」的配乐 RMS 只比前一段高约 3–4 dB。
  - 【测】频谱重心 12–90 s 为 174–428 Hz，0–12 s 仅约 84 Hz。
  - README 写明配乐为 `audio/synth.py` 程序合成。
- 为什么是问题：90 s 里基本是同一个和弦循环，高潮缺乏编配层次（没有新声部，也没有明显的力度与织体变化）。
- 影响：情绪递进主要靠旁白和画面撑着；配乐是「AI 味」的主要来源之一（见 §8）。
- 建议：54 s 处加入新的旋律层或打击乐层，并让能量更明显地抬升（例如 +5–6 dB 体感，同时保持整体 −14 LUFS）；74 s 第五幕换一个和声色彩；或者改用免版税的真实乐器曲库。若坚持程序合成，至少在每 8 小节做配器增减。
- 优先级：可选优化（高）。
