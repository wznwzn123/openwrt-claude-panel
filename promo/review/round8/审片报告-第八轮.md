## 1. 总体评价

这是一支**内容真实、信息组织清楚、技术参数合格，但视听语言偏模板化**的产品说明型宣传片。

**强项**
- 片中出现的功能几乎都能在仓库代码或官网找到依据：
  - 32 个连接器工具、30 秒看门狗、约 2 MB 面板、ucode + uhttpd、六款扩展套件、改配置前自动备份。
  - PushPlus 微信推送、托管版 5 分钟安装、注册送 7 天试用、MIT 开源。
- 第四幕「一句话 → 调用工具 → 底层状态变化」的因果链和数据前后一致，是全片最有说服力的段落。
- 演示数据和画面加速都有角标说明，合规改写也执行到位。

**弱项**
- 画面：约 80 秒都是同一套蓝紫渐变光斑背景，配毛玻璃卡片和手机模型。
  - 约 45% 的半秒窗口几乎没有运动【测】。
  - 雷达、取景框、伪遥测等 HUD 元素较多，「PPT + 模板科技风」感明显。
- 声音：免费 TTS 旁白的辨识度很高，品牌名「Panel」在转写中完全识别不出【测】，实际听感【待确认】。
  - 音乐动态范围很窄（LRA 3.8 LU），声像接近单声道（L/R 相关 0.98）【测】。
  - 音乐缺少高潮推进，主观感受【待确认】。
- 交付：主片和上传版第四幕有 4–5 处单帧渲染故障，文字或代码块闪掉一帧。剪映草稿底片在其中三处已核对是干净的，说明这是主片渲染的偶发问题，可以低成本修复。

**一句话结论**：没有 S 级问题，产品可信度不受威胁。按「专业商业宣传片」标准，目前处在**合格线边缘（69.5 分）**。修好 A-1 的单帧故障是发布前的硬门槛。

## 4. 问题清单

### S 级（严重）
**无。** 没有发现虚构功能、重大事实错误、严重音频故障或二维码导流风险。

### A 级（明显缺陷）

#### A-1　第四幕单帧渲染故障（主片和上传版都有）【测】【看】
1. **时间戳（帧号以 60 fps 计）：**
   - **59.967 s（第 3598 帧）**：发送后输入框里的占位文字和发送按钮同时消失一帧。
   - **64.150 s（第 3849 帧）**：正在打字的「看看现在 → 看看现在哪」中间，输入框整框变空一帧，按钮也消失。
   - **64.517 s（第 3871 帧）**：「看看现在哪台设备在占 → …在占满」中间，同样整框变空一帧。
   - **71.717 s（第 4303 帧）**：右侧 uci 代码块（`dhcp.@host[-1]…`）整块消失一帧，约 23 万像素突变。
   - 疑似：**66.583 s（第 3995 帧）**，放大卡片第一帧残留了上一个状态的线路列表；**71.217 s（第 4273 帧）**，右卡片变成一块空白亮框。这两处可能是转场残影，需要用户逐帧确认。
2. **具体表现**：前后两帧一致，只有中间一帧缺内容（逐帧差分：与前后帧差异大，前后帧彼此差异小），属于典型的单帧渲染丢失。
3. **为什么是问题**：60 fps 下一帧约 17 ms，但发生在亮色文字或代码块上，会被看成「闪一下」，而且集中在全片最重要的 AI 演示段。
4. **对成片的影响**：认真看的观众（B 站技术向受众爱逐帧看）会觉得「界面在闪 / 做得糙」，削弱第四幕的可信感。上传版（`-上传版.mp4`）同样有这些帧【测】。
5. **修改建议**：这些帧在剪映草稿的无字幕底片 `assets/plate.mp4` 中**是干净的**（59.967 / 64.150 / 71.717 s 三处已核对，孤立像素数分别为 17 / 0 / 0），说明是主片渲染时的偶发问题。重渲第四幕（约 58–74 s），或只替换故障帧，再用附录的逐帧差分脚本复检。
6. **优先级**：**P0（发布前必须修）**。

> 已排除的「疑似故障」（目视确认是设计动画，**不算故障**）：
> - 6.000 s（第 360 帧）：灰色闪光，亮度 32 → 59 → 93 → 61 → 44 先升后降，是设计内的闪白转场。
> - 3.6–5.55 s：三联屏的 RGB 错位 / 扫描线抖动，属于「老后台」的故障风格化。
> - 11.8 s：中心光晕爆闪。
> - 16.67–16.78 s、18.73–18.83 s：深浅色切换的圆环扩散。
> - 39.983 s（第 2399 帧）：流量卡片整体上移约 7 px 一帧，与「顶破天花板」同时发生，是冲击震动，草稿底片里同样存在。
> - 40.2 s：柱子光束冲出卡片，属于坐标轴重标动画。

#### A-2　画面同质化，PPT 感和手机模型重复【测】【看】
1. **时间戳**：全片，以 12–53.5 s 和 74–90 s 最明显。
2. **具体表现**：
   - 约 80 秒都是同一种蓝紫渐变光斑背景，配毛玻璃卡片。
   - 手机模型出现在 0–1.9 s、12–53.5 s、74–81.5 s，合计约 50 秒。
   - 半秒窗口的运动能量统计：179 个窗口中有 80 个（45%）平均帧差小于 0.5/255，几乎静止【测】。
   - 长静止段：13.0–16.5 s、20.5–27.5 s（只有卡片逐条出现）、29.5–34.0 s、48.5–53.5 s（运动能量约 0.22，基本只有颗粒）、74–81 s。
3. **为什么是问题**：任务书明确检查「PPT 感」「重复的手机模型展示」「空间层次、景深和光影变化」。片中没有实拍、没有真实空间光影，镜头运动主要是平面推拉和卡片淡入。
4. **对成片的影响**：观众会把它归类为「模板科技宣传片」，记不住具体镜头，商业质感上不去。
5. **修改建议**（不改功能口径）：
   - 每一幕至少换一个不同的视觉母题：
     - 第一幕用真实手机屏录（双指放大 LuCI）或手持实拍；
     - 第三幕把三手机并排换成单手机满屏，配手指点击轨迹；
     - 第五幕用真实路由器硬件的特写（指示灯 / 网线拔插），替换 HUD。
   - 背景按幕区分色温：第一幕冷灰，第二、三幕蓝，第四幕暖橙（Claude 色），第五幕回到深蓝。
   - 48.5–53.5 s 的静止段至少加一个推镜或焦点转移。
6. **优先级**：P1（影响观感上限；工作量较大，可以分步做）。

#### A-3　品牌名在旁白中可能听不清，TTS 辨识度高【测】+【待确认】
1. **时间戳**：11.86–13.9 s（「OpenWrt 克劳德 Panel」），另有 7.84 s 和 54.42 s 等处。
2. **具体表现**：
   - faster_whisper small 自由转写把这句听成「克劳德 **Taino**」或「客老的 **Tanel**」。
   - 用 `initial_prompt` 明确提示「OpenWrt Claude Panel」后，「Panel」一词的词级概率仍是 **0.00**【测】，说明这个英文词的发音与常规读法差异很大。
   - 其他转写偏差：「管法」两次被听成「关法 / 关卡」（概率 0.4）；「靠」被听成「耗」（0.57）；「看门狗」被听成「看门口」。这些可能是模型对同音字的局限，**需要用户试听确认**。
3. **为什么是问题**：品牌名是传播的核心，如果观众用耳朵记不住「Panel」，口碑传播和搜索都会受损。
4. **对成片的影响**：短视频平台很多人不看字幕。品牌只靠落版文字传递，记忆点会变弱。
5. **修改建议**（在「免费 TTS、不用真人」的前提下）：
   - 单独重合成 a2 句的品牌名，可尝试「Panel」→「潘诺」或「派闹」的谐音读法，也可以在品牌名后加 150–250 ms 停顿，用 SSML `<break>`。
   - 或者让旁白只说「OpenWrt 克劳德面板」，字幕仍写 Panel（与「Claude 读作克劳德」同一处理思路）。
6. **优先级**：P1（**待用户试听确认后再决定**）。

## 附录：复现方法（只读，工作文件在 `promo/review/round8/work/`）

- **元数据**：`ffprobe -show_entries format=duration,bit_rate:stream=codec_name,width,height,r_frame_rate,nb_frames,channels,sample_rate`
- **黑场和静止检测**：`ffmpeg -i <mp4> -vf blackdetect=d=0.1:pix_th=0.10,freezedetect=n=0.001:d=1.0 -f null -`
- **响度**：`ffmpeg -i <mp4> -af ebur128=peak=true -f null -`；`astats`；`silencedetect=n=-50dB:d=0.3`
- **逐帧差分**：全片缩到 320×180 灰度，计算 d(i−1,i)、d(i,i+1)、d(i−1,i+1)。
  - 判定条件：min(前, 后) > 1.5 且 d(i−1,i+1) < 0.4×min；
  - 另做 20×20 块级检测（块内前后差都大于 6，且前后帧彼此差小于 0.3 倍）；
  - 所有候选都抽取全分辨率三连帧目视确认。
  - 汇总图：`work/fr/c3849.jpg`、`c3871.jpg`、`c4303.jpg`、`g360.jpg`、`m_330.png`、`cands2.jpg`。
- **二维码**：每秒 4 帧，`cv2.QRCodeDetector.detect` / `detectAndDecodeMulti`，候选截图在 `work/qrcands.jpg`。
- **转写**：faster_whisper small（int8），16 kHz 单声道 float32 输入；全片结果在 `work/asr.txt` / `asr.json`，竖屏在 `work/v_asr.txt`；品牌名段落另用 `initial_prompt` 复测。
- **齿音**：5–10 kHz 四阶带通，20 ms 窗口能量。
- **人声和音乐比例**：用人声几乎没有能量的 30–80 Hz 频段（人声 stem 在该频段约 −53.6 dB），对比主片与 BGM stem，推算音乐电平和闪避量（误差约 ±2 dB）。
- **上传版对比**：`ffmpeg -i 上传版 -i 主片 -lavfi psnr,ssim`；音频解码后做 MD5。
- **剪映草稿**：Python `zipfile` 读取 `draft_content.json`，统计轨道、音量、关键帧和素材引用；底片故障帧核查后已删除解压出的 `plate.mp4`。
