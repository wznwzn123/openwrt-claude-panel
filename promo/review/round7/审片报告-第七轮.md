## 1. 总体评价

这是一支**做工干净、信息准确度高、但「商业片质感」与「记忆点」不足**的产品说明型宣传片。

长处很实在。手机界面全部来自仓库代码的实机渲染，第三、四幕把真实 UI、真实连接器工具名、真实交互逻辑（授权卡、改前自动备份、uci 写入）连成一条可信的使用链。技术交付参数无可挑剔：-14.0 LUFS，真峰值 -1.8 dBFS，faststart，零解码错误，零卡帧。

短板同样明显，可以概括为五点：

1. 全片几乎是「深色极光渐变 + 玻璃卡片 + 浮空手机」一套模板贯穿到底。没有真实拍摄或真实操作，PPT 和模板感偏重。
2. 旁白稿过密：全片约 290 音节/分，旁白占片长 85%，第四幕超过 320 音节/分【测】。音乐与画面没有呼吸空间，情绪弧线被压平（全片 LRA 仅 3.0 LU【测】）。
3. 第五幕 HUD 中「DNS 解析 · 异常 → 已自动修复 ×2」在仓库中找不到对应的修复逻辑，属于事实风险。
4. **主片有多处单帧渲染故障【测】**：
   - 47.03s 左侧手机屏幕整帧发黑；
   - 第四幕三次打字输入时，输入框文字和高亮逐帧闪没（59.2–59.5s、63.85–64.0s、68.2–68.6s）；
   - 72.47s 一个空白暗色矩形压住 DHCP 卡片；
   - 77.10s 全画面单帧提亮。

   常规的黑场、静帧检测器抓不到这类问题，是逐帧差分扫描发现的。
5. 几处声画错位，叠加 TTS 配音与程序合成音乐，构成了主要的「AI 味」。

**一句话判断：** 主片在修正 1 处事实风险、重渲几段单帧故障后可以发布，但它目前是一支「合格的产品介绍片」，还不是「让人想转发的宣传片」。附带交付物中，**剪映草稿存在严重缺陷（后半段人声、BGM、字幕全部缺失；16:00 替换后的新包依旧如此），不能直接交付**。

### A 级

**A-1　74.5–81.8　第五幕 HUD「[02] ▲ DNS 解析 · 异常 → 已自动修复 ×2」缺少代码依据**

- 表现：HUD 第二行写 DNS 异常已被自动修复 2 次，橙色高亮，是该画面的视觉焦点。
- 依据【测】：
  - `src/bin/cmcp-watchdog` 对 DNS 只做检测、记录和推送（第 292–296 行 `ev err dns "DNS 解析失败…"`），全文件的修复动作只有：重启隧道 `restart_tunnel`、重启面板服务、清缓存、内存不足时重启代理插件。
  - 仓库内未找到 DNS 修复逻辑（dnsmasq 重启只出现在 `cmcp-tunbypass` 的直连配置流程里）。
  - 面板自身文案「断了会自动修复」是泛称。
- 为什么是问题：这是把「检测并告警」包装成「自动修复」，属于任务书第三节「将尚未实现的功能包装成已实现」的风险。懂行的观众对照代码能发现。
- 定性：按本轮可见代码判为**事实风险**；若开发者另有修复路径，请给出出处，再改判为「待核实」。
- 修改建议（任选其一，均与真实功能一致）：
  - 改为「[02] ▲ DNS 解析 · 异常 → 已记录并推送提醒」；
  - 或换成真实有修复动作的项：「[02] ▲ 面板服务 · 无响应 → 已自动重启」。
- 优先级：发布前必须改（工作量很小）。

**A-2　全片（尤其 53.2–73.5）旁白过密，挤掉了情绪和节奏空间**

- 表现【测】：
  - 旁白共 371 个音节，有声时长 76.7s，占片长 85%，平均约 290 音节/分。
  - 第四幕 a4a 约 363、a4c 约 333、a4d 约 327 音节/分。
  - 合成参数为全局 +4% 语速，a3b 再 +6%。
  - 中文商业片口播常见舒适区约 220–260 音节/分（行业经验值，非硬标准）。
- 为什么是问题：音乐几乎没有独奏留白（全片 LRA 3.0 LU），第四幕本应是全片高潮，却变成了读说明书。观众来不及看清画面里的对话卡片，「AI 解说号」观感也被放大。
- 影响：节奏单一，情绪递进弱，AI 味上升。
- 修改建议：
  - 文案总量删减约 15–20%（具体删法见第 7 节）；
  - 取消 a3b 的 +6%，全局语速回到 0%；
  - 第二幕末（约 27.5s）、第四幕开场（约 54s）、落版前（约 84s）各留 1–1.5 秒纯音乐。
- 优先级：强烈建议（需要重新合成旁白和混音）。【主观部分·待用户试听确认密度是否可接受】

| 3553；3569–3571；3583–3589 | 59.22–59.82s | 第一条指令打字时，输入框文字「把超清影音通道…」和橙色高亮在单帧之间时有时无 |

- 优先级：发布前必须修。

## 5. 分幕评价

**第一幕（0–11.8s）· 痛点**

- 功能上成立：手机看老后台，端口映射失败，CGNAT 连不上家，「OpenWrt，换一种管法」。
- 问题：
  - 开头 3 秒靠闪光音效和推镜制造冲击，但画面是灰色英文后台，大众观众抓不到痛点。
  - 3.0–5.8 的三联窗太像 PPT。
  - 6.0–8.5 的顶部答案句与旁白痛点打架（B-1）。
- 亮点：6.0–10.5 的 OPENWRT 字母蒙版是全片最好的概念镜头；11.0–11.8 巨字「OP」穿越转场衔接有力。
- 评分感受：概念好，执行偏模板。

**第二幕（11.8–28.4s）· 产品是什么**

- 主视觉加分层拆解，信息清楚，节奏稳。
- 13–16s、22–27s 两段运动很慢（运动能量约 1–3【测】），基本靠旁白撑。
- 卖点卡的写法诚实（cloudflared 另计）。
- 这一幕是全片「说明书感」最强的一段：三个参数卡依次弹出，缺少一个让人「哇」的瞬间。

**第三幕（28.4–53.8s）· 常用功能**

- 真实 UI 证据最充分的一幕：套件识别、线路测速与自动切换、流量柱状图、定时断网、主屏幕和安卓 App、多路由器。
- 问题：
  - 25 秒塞了 7 个功能，三机并排加两机并排的手机样机重复使用；
  - 42.5–45.6 两处声画错位（B-2、B-3）；
  - 49.5–53.6 静止拖沓（B-4）。
- 39–42s 柱状图「冲顶、刻度重标」动画做得好。

**第四幕（53.8–73.9s）· AI 版**

- 立意最好的一幕：32 工具网格 →「说一句，它来办」→ 三条指令由易到难（只读 → 读写 → 需要授权的危险操作），逻辑递进清楚，技术细节准确（uci 路径、reload dhcp、修改前快照）。
- 但它是「信息高潮」而不是「视听高潮」：画面仍是玻璃卡片，旁白语速全片最快（约 330 音节/分），观众读不完对话气泡；「两把钥匙」重复 3 次（B-8）；卡片裁切（B-10）。
- 三次打字时输入框逐帧闪没，72.47s 还有闪块（A-3）。这一幕是全片单帧故障最集中的地方。
- 建议把这一幕的旁白减到只讲指令，让结果卡和音效来「说话」。

**第五幕（73.9–90s）· 守护与落版**

- 看门狗 HUD 加真实「断线记录」页加推送卡，信息丰富。
- 问题：
  - 视觉是最典型的「伪遥测 HUD」（WATCHDOG · ALL CHECKS OK · AUTO-HEAL · LOG）；
  - DNS 自动修复的事实风险（A-1）；
  - 备份成功推送与实际不符（B-6）；
  - 「五分钟装好」口径混淆（B-7）；
  - 落版晚于旁白（B-5）。
- 落版本身干净，但缺少一句能记住的收尾语，音乐渐隐收尾（B-12）。

## 6. 声音评价

- **旁白**【测+主观】：
  - 可懂度高，转写准确率高；电平稳定（压缩后峰值因数约 18 dB）。

  - 0–12s 95 BPM 暗夜脉冲 → 11.8s Sub Drop → 116 BPM 极简电子，结构上有设计，54s、82s 有推高。

  - 95 个，密度高、电平低，与画面卡点基本对齐（按 cues.json 时间与画面事件核对）。

- **混音与母带**【测】：
  - -14.0 LUFS，TP -1.8 dBFS，无削波，无爆音，无突兀切断；首尾干净。
  - 人声对音乐有效余量约 12–15 dB。
  - 【待用户试听】闪避抽吸感（B-11）。
