## 1. 总体评价

这是一支**工整、统一、信息量很大的产品动态图形片（motion graphics explainer）**，但还**不是电影级的商业宣传片**。

**最大的长处是真实。** 手机界面是用仓库代码实机渲染的，第三、四幕「测速 → 超时 → 自动切线路」「一句中文指令 → 调工具 → 返回结果」两段，把产品价值讲得清楚、可信。深色极光配色、Noto Sans SC 排版和玻璃材质全片一致，技术交付也干净：无黑场、无卡帧、无削波，响度准确落在 −14 LUFS。

**最大的问题有五个：**

1. **声音像 AI 做的。** 云扬 TTS 配音覆盖了 88% 的时长，同时塞进 31 条四字格短语，听起来像「念功能清单」。程序合成的配乐在前 54 秒几乎只有 200 Hz 以下的低频，手机外放基本听不到；到 54 秒又被突然推高约 4 LU。
2. **画面重复且多次停住。** 12–54 秒约 40 秒在展示漂浮的 2.5D 手机样机；13–16、22–27.5、49.5–53.9 秒画面近乎静止；伪遥测数字、雷达、取景框、词云这些模板化科技元素让 PPT 感和 AI 味都很重。
3. **最关键的 AI 演示段夸大了实际体验。** 第四幕把 Claude 多秒级的对话压缩成 0.6 秒，旁白配「毫秒级切换」。屏幕上的防火墙规则在 OpenWrt 里不成立（缺 `dest`），还跳过了产品自己要求的「改防火墙先征得确认」。
4. **安全表述没有加条件。** 「端到端加密云端备份」实际上只在路由器装有 openssl 或用户手动开启后才加密。官网原文写着「没开启加密的备份仍然原样存在云端」。
5. **合规口径前后矛盾。** 用户要求「不出现境外平台名」「二维码打码防站外导流」，但落版上有 GitHub，旁白和屏幕都在把人导向网址。

**结论：** 现在的版本**不建议作为正式宣传片发布**，综合得分 **63 / 100**（60–69：质量不足，需要重点优化）。好在大部分硬伤是文字、时序和混音层面的，改动成本不高。必须修改的项完成后，有望进入 70 分段；要上 80 分，需要真人配音和第二、三幕的节奏重剪。

## 4. 问题清单

每个问题都按六要素写：**时间戳 / 具体表现 / 为什么是问题 / 对整体的影响 / 修改建议 / 优先级**。
优先级：P0 必须在发布前处理；P1 强烈建议；P2 建议；P3 可选。

### S 级（可能影响可信度或导致无法发布）

#### S1 导流与境外平台名：和用户自定的合规口径冲突
- **时间戳**：85.0–90.0 落版「GitHub wznwzn123/openwrt-claude-panel」「★ 点赞支持 · GitHub 点亮 Star」；82.93–85.42 旁白和字幕「访问 yrlove520.com」；80.5–82.4 终端里完整的下载网址 `https://yrlove520.com/dl/…`；竖版 60s 的 54–60 s 同样有这些内容。
- **具体表现**：用户要求「全片不出现任何地区名、境外平台名」「二维码一律打模糊，以免被判为站外导流」。片中确实没有二维码（检测 0 命中），但落版明文出现 GitHub（境外平台名）两次，旁白和屏幕两次把观众导向站外网址。
- **为什么是问题**：二维码打码的初衷是规避站外导流判定，网址口播 + 屏显 + 仓库地址属于同类行为，这个初衷就被落版抵消了。GitHub 不在用户列出的允许保留名单里；旁白里的「Cloudflare」是用户明确允许的。
- **影响**：投抖音、视频号、小红书时，有被限流或审核不通过的风险（各平台现行规则**待核实**）；B 站通常可接受片尾网址，风险较低。竖版本来就是为这几个平台做的，风险更直接。
- **修改建议**：落版和第五幕按平台出两版。
  - **B 站版**：保留官网；GitHub 可保留，或改成「开源仓库见简介」。
  - **抖音 / 视频号 / 小红书版**：去掉 GitHub 和网址；终端命令里的完整 URL 打码或换成「安装命令见主页简介」；口播改成「想试试，看主页简介」。
  - 「Claude」「Cloudflare」是否保留，请用户按平台口径最终确认。
- **优先级**：P0（需要用户决定口径）。

### A 级（明显缺陷，严重影响观感或可信度）

#### A1 AI 演示把多秒级对话压缩成 0.6 秒，并配「毫秒级切换」
- **时间戳**：59.20–62.15（字幕「一句中文指令 / 毫秒级切换高速专线」）；三条指令都是发送后约 0.59 秒就返回结果：59.97→60.56、63.70→64.29、67.13→67.72（帧上可见，与工程 `src/act4.json` 一致）。
- **具体表现**：画面上 Claude 在 0.6 秒内完成「理解 → 调工具 → 返回结果」，旁白说「毫秒级切换」。
- **为什么是问题**：Claude 通过自定义连接器调用工具，端到端通常要几秒（含模型推理和网络往返；具体时延取决于 Claude 服务，**待核实**）。「毫秒级」最多只适用于路由器端执行切换这一步。片中只标了「界面为演示数据」，没有标「画面已加速」。
- **影响**：这是全片高潮和核心卖点。用户第一次实际使用就会发现落差，直接损害「AI 版」的可信度。
- **修改建议**：每条指令之间加 1.5–3 秒「Claude 正在思考 / 调用工具：线路切换 · 延迟测试」的过程（可以用快进感处理），角落加「画面已加速」小字；旁白去掉「毫秒级」，改写见「文案评价」第 9 条。
- **优先级**：P0。

#### A2 屏幕上的防火墙规则不成立，而且跳过了产品自身的确认机制
- **时间戳**：66.12–70.30；代码块清晰停留在 67.8–70.3（全分辨率帧 `work/full/t068.5.png`）。
- **具体表现**：`config rule 'pause_kids_tablet' / option src 'lan' / option src_mac … / option start_time '23:00:00' / option stop_time '07:00:00' / option target 'REJECT'`，状态标「✓ 已写入生效」，没有任何确认步骤。
- **为什么是问题**：
  - OpenWrt 防火墙规则只写 `src` 不写 `dest` 时，只匹配发往路由器本机的流量（input），**拦不住平板上外网**。
  - 跨午夜的 `start_time > stop_time` 在 fw4 下怎么处理，**待核实**。
  - 产品真实的「定时断网」走的是 `cmcp-pause`（iptables mangle 表 PREROUTING 链加 `-m time`），不是这条 UCI 规则。
  - 连接器 `uci_set` 工具的说明写着「改错 network / firewall 可能导致整个路由器断网……这类修改必须先向用户说明风险并确认」（`src/www/cgi-bin/mcp` 第 3116 行），片中却是直接写入。
- **影响**：B 站 OpenWrt 用户正是核心受众，大字展示 3 秒的错误配置会被截图挑错；同时把「先确认再执行」这个安全卖点藏掉了。
- **修改建议**：
  1. 规则补上 `option dest 'wan'` 和 `option name`，并实测 fw4 跨午夜的行为；或者改为展示产品真实的「设备暂停 · 儿童平板 · 每天 23:00–07:00」结果卡。
  2. 在 66.9–67.2 之间加一拍：Claude 问「这会修改防火墙，确认执行吗？」→ 用户点「确认」。这一拍反而能支撑「双钥匙安全隔离」。
- **优先级**：P0。

#### A3 「端到端加密云端备份」没有加条件
- **时间戳**：74.51–75.65 旁白和字幕「加密云端备份」；74.6–80.0 推送卡「每日端到端加密云端备份已就绪 · 保留 10 份 · 可一键恢复」；80.5–83.0 卡片「端到端加密备份 · MIT 协议开源」。
- **具体表现**：「端到端加密」被说成默认、无条件的。
- **为什么是问题**：`src/bin/cmcp-backup` 第 84 行只有在「未关闭加密且路由器上有 openssl」时才加密上传；`cloud/README.md` 写「有 openssl 就先加密再上传……没有的可以在面板点『开启加密』」；官网原文「**没开启加密的备份仍然原样存在云端**」。另外，云端备份只有自建完整版和托管版才有（README 功能表）。
- **影响**：属于夸大安全性（任务书第三节第 3 条点名的重点检查项）。备份里有 Wi-Fi 密码、宽带账号和登录密钥，一旦被质疑，杀伤力大。
- **修改建议**：推送卡改为「今日云端备份完成（已加密）· 保留 10 份」，并在卡角或字幕加小字「开启加密后在路由器本地加密 · 完整版 / 托管版」；旁白改法见「文案评价」第 12 条。
- **优先级**：P0。

#### A4 前 54 秒配乐在手机上近乎缺席，情绪曲线断层
- **时间戳**：0–54.0（尤其 28–54）；54.0 突然推高。
- **具体表现（测量）**：说话时段人声比配乐高：A1 19.8 dB、A2 14.0 dB、A3 16.8 dB、A4 6.2 dB、A5 6.6 dB。1–4 kHz 频段内，配乐在 A1–A3 比人声低 25–34 dB。配乐频谱质心：A1 70 Hz、A3 189 Hz。分幕响度 A3 −16.3 → A4 −12.5 LUFS。
- **为什么是问题**：手机扬声器 200 Hz 以下基本发不出声，所以抖音、B 站手机端观众在前一分钟几乎只听到 TTS 念稿和零星音效；第三幕是最长的一幕（26 秒），却是全片声音最「空」的一段。
- **影响**：「音乐是否有清晰的情绪递进」不达标：前半段没有情绪托底，后半段突变。
- **修改建议**：重新混音时，A1–A3 的配乐抬高 6–8 dB（让人声比配乐保持在约 10–12 dB），并在 200 Hz–2 kHz 加入可闻的中频层（钢琴、拨弦、pad）；人声段用侧链压缩代替整体压低；3→4 幕响度差控制在 2 LU 以内。听感**待用户用手机外放试听确认**。
- **优先级**：P1。

#### A5 旁白：TTS 新闻腔、几乎铺满、四字格密集
- **时间戳**：全片；最密的是 11.75–28.66、28.9–50.54、71.03–87.22。
- **具体表现（测量）**：旁白覆盖 88%；41 条字幕短语里 31 条是四字格或含四字格结构，其中 6 条是「四字 + 四字」对仗。机器转写的典型误识别：「受困于→受惠于」（意思相反）、「至此→致死」、「破界→破解」、「晦涩→绘色」、「层层端口映射→曾层端口硬设」、「毫秒→好秒」×2、「看门狗→看门口」、「回滚→微滚」、「言出法随→延出法随」。
- **为什么是问题**：书面词加上 TTS 的同一种语调，听众要靠字幕才能跟上。「破界登场」听起来像「破解登场」，对一个管路由器 root 权限的工具是负面联想。转写只是可懂度的旁证，**听感待用户确认**。
- **影响**：机械感最强的来源，也是 AI 味的第一来源；观众「一耳」就能判断这是 AI 配音（**待用户确认**）。
- **修改建议**：真人重录（或至少换更自然的音色，用 SSML 控制停连和重音）；按「文案评价」改写成口语；让旁白覆盖率降到约 70%，在 11.8、28.0、54.0、84.5 前后留出 0.8–1.5 秒，让音乐和画面接住情绪。
- **优先级**：P1。

#### A6 手机样机重复出现，多处长时间近静止（PPT 感）
- **时间戳**：12.0–54.0 约 40 秒以漂浮 2.5D 手机为主（单机 → 三机 → 单机 + 图表 → 双机），71.6–80.0 再次单机 + HUD；近静止段（逐帧差分均值 < 0.4）：13.0–16.0、22.0–27.5、30.0–34.0、49.5–53.9。
- **具体表现**：同一部手机模型、同一张首页（78.9 Mbps / 44.1 GB）在 12–28、44.5–54 反复出现；49.5–53.9 两台手机静止约 4.4 秒。
- **为什么是问题**：任务书点名「是否存在重复的手机模型展示」「是否存在明显 PPT 感」。全片没有一个真实空间镜头（人、家、路由器实物、手部操作）。
- **影响**：中段注意力流失。第二、三幕合计 42 秒的观感接近「功能幻灯片」。
- **修改建议**：
  - 第二幕 13.0–16.0 产品名出现时，用面板真实操作录屏代替静态样机；
  - 第三幕的三机并排压缩为一次；
  - 44.5–54.0 双机段裁到 6 秒以内；
  - 至少插入 2–3 个真实场景镜头（例如 42 s 前后「孩子平板到点断网」的真实屏幕、路由器指示灯、手在沙发上操作手机）；
  - 近静止段至少加慢推或焦点转移。
- **优先级**：P1。

#### A7 主信息不聚焦：约 20 项功能平铺，没有一句能单独传播的话
- **时间戳**：全片；产品名首次出现在 11.85 s，此前 6.0–11.8 的主视觉是「OPENWRT」。
- **具体表现**：90 秒依次罗列 ucode、2MB、隧道、六套件、测速、切线路、流量、定时断网、PWA、安卓、面板锁、多路由、连接器、双钥匙、30+ 工具、三条 AI 指令、看门狗、备份、推送、断电判断、MIT、五分钟部署……落版语「即刻唤醒你的智能路由」是通用句。
- **为什么是问题**：观众记不住 20 个点；宣传片应该有 1 个主张 + 3 个证据。
- **影响**：「是否让观众快速理解产品是什么、是否有足够强的记忆点」只能算部分达标。
- **修改建议**：用一句主张统领全片，例如「不用公网 IP，在手机上管好家里的路由器；装 AI 版，说一句就行」。证据只保留三组：手机面板、自动守护、AI 对话，其余功能放进 79–83 s 的一屏清单。具体改写见「文案评价」。
- **优先级**：P1。

## 5. 分幕评价

**第一幕 0–11.8 s：痛点与「终结」（7/10）**
- 0.15 秒起画，0.5 秒出现红色报错条，1.0 秒闪白进入全屏 LuCI。痛点具体（CGNAT、端口映射失败），对 OpenWrt 用户来说开头 3 秒是有效钩子。
- 但取景框 HUD（ISO 3200 · REC）、三窗 CAM 01/02/03、雷达和伪遥测数字都是模板化科技元素。1.0–3.0 秒是大面积白底（平均亮度 206），和全片暗调风格割裂。
- 6.0–11.8 的 OPENWRT 镂空字是全片最好的字体设计时刻，配文有歧义（B6），文字层堆叠（B7）。旁白「掌心方寸之间……受困于内网孤岛」太书面。

**第二幕 11.8–28.0 s：产品登场与架构（5.5/10）**
- 产品名出现方式偏平：静态手机 + 文字淡入，13.0–16.0 近静止。
- 主题切换（浅色 → 深色 → 相册磨砂）证明了真实的「外观」功能，但节奏慢。20–28 的分层拆解是亮点，用 `ps` / `du` 讲轻量架构有说服力。
- 问题：标题、副标、卡片、字幕四层同义；「仅占 2MB」缺少 cloudflared 说明（B1）；22.0–27.5 画面近静止。

**第三幕 28.0–54.0 s：功能巡礼（5.5/10）**
- 35–38.5 的「超时 → 自动切换」真实可信；38.6 转场到流量柱状图有设计感；42.5「暂停儿童平板上网」弹层对应真实功能。
- 但这一幕最长（26 秒），配乐几乎听不到（A4）。三机并排、双机并排重复（A6），49.5–54 是死区（B9）。「生物面板锁」「原生安卓多端协同」措辞失准（B3），流量数据前后矛盾（B4）。

**第四幕 54.0–71.7 s：Claude 高潮（6.5/10）**
- 节奏最好的一幕：约 1 秒一次推拉，指令逐字输入，结果实时映射，配乐和低频冲击明显加强。叙事结构「说一句 → 调工具 → 结果 → 备份可回滚」清晰，是全片最有差异化的段落。
- 54.0–58.0 的漂浮词云是典型 AI 模板画面。0.6 秒响应加「毫秒级」夸大（A1），防火墙规则不成立且跳过确认（A2），这两处直接打在最关键的可信度上。

**第五幕 71.7–90.0 s：守护与落版（6/10）**

## 9. 最终发布建议

**是否建议正式发布？**
